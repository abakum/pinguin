# Plan: `make syso` — автоматический пуш тега + переход на теги `vX.Y.Z`

## Контекст

`make syso` в Makefile инкрементирует patch-часть высшего git-тега, создаёт тег локально и собирает `pinguin.exe`. Тег на origin не отправляется. Теги сейчас формата `0.0.1` (без `v`); на origin есть `refs/tags/0.0.1` (коммит `f36e22b`), локально — `0.0.1`. Remote — `origin` (github.com/abakum/pinguin).

Решения пользователя:
1. Пушить тег автоматически внутри `make syso`.
2. Перейти на теги с префиксом `v` (стандарт Go SemVer).

## Изменения

### 1. Makefile — цель `syso` (строки 93–98)

```make
syso:
	@base=$$(echo $(VERSION) | sed -E 's/^v?([0-9]+\.[0-9]+\.[0-9]+).*/\1/'); \
		[ -n "$$base" ] || base=0.0.0; \
		major=$${base%%.*}; rest=$${base#*.}; minor=$${rest%%.*}; patch=$${rest##*.}; \
		next="v$$major.$$minor.$$((patch+1))"; \
		echo "Tagging $(GIT_COMMIT) as $$next"; \
		git tag $$next && git push origin $$next && $(MAKE) win VERSION=$$next
```

Отличия от текущей версии:
- regex `^v?...` + `sed` вместо `grep -oE`: понимает и старые (`0.0.1`), и новые (`v0.0.2`) теги; на переходный период это не нужно строго (высший тег по `--sort=-v:refname` будет `v...`, `grep -oE '^[0-9.]+'` на нём даст пусто → fallback `0.0.0` → следующий тег `v0.0.1`, конфликт со старым `0.0.1` невозможен из-за префикса, но нумерация скатится к 0.0.1 — нежелательно). Поэтому парсинг делаем устойчивым к `v`.
- тег создаётся сразу с префиксом: `v0.0.2`.
- порядок `git tag && git push && make win`: пуш обязателен до сборки.

### 2. Makefile — VERSION по умолчанию (строка 10)

`git tag --sort=-v:refname` корректно сортирует и `v`-теги (refs с префиксом сортируются по тем же правилам version). Убедиться, что `head -n1` вернёт `v0.0.2`, а не `0.0.1`: `--sort=-v:refname` сравнивает по версии, `v0.0.2` > `0.0.1` — ок. Оставить как есть.

### 3. Makefile — числовые части версии (строки 16–20)

`VERSION_MAJOR/MINOR/PATCH` парсят `$(VERSION)` через `grep -oE '^[0-9]+'` — на `v0.0.2` даст пусто → MAJOR=0. Поправить на устойчивый парсинг:

```make
VER_NUM:=$(shell echo $(VERSION) | sed -E 's/^v?([0-9]+\.[0-9]+\.[0-9]+).*/\1/')
VERSION_MAJOR:=$(word 1,$(subst ., ,$(VER_NUM)))
VERSION_MINOR:=$(word 2,$(subst ., ,$(VER_NUM)))
VERSION_PATCH:=$(word 3,$(subst ., ,$(VER_NUM)))
```

(значения по умолчанию 0 через `$(if ...)` сохранить либо — пустое слово даст пусто; добавить `|| echo 0` обработку: `VERSION_MAJOR:=$(if $(VERSION_MAJOR),$(VERSION_MAJOR),0)` и аналогично для остальных).

### 4. Makefile — справка `help` (строка 37)

```
@echo "  make syso     - increment patch tag (vX.Y.Z), push tag to origin, then make win"
```

### 5. Миграция тега `0.0.1` → `v0.0.1` (однократно, вручную)

Тег `0.0.1` уже запушен на origin (`f36e22b`). Пересоздать с префиксом и удалить старый:

```bash
git tag v0.0.1 0.0.1
git push origin v0.0.1
git tag -d 0.0.1
git push origin :refs/tags/0.0.1
```

Порядок: сначала создать и запушить `v0.0.1`, затем удалять старый — окно без тега минимально. Если на GitHub по тегу `0.0.1` есть Release — перенести/переименовать вручную через веб-интерфейс (в репозитории не проверялось).

Выполнять миграцию до первого запуска обновлённого `make syso`, чтобы следующим тегом стал `v0.0.2`.

## Сценарии

- Успех: `vX.Y.Z` создан, отправлен на origin, `pinguin.exe` собран с этой версией.
- Пуш не удался (сеть/права): `make` падает до сборки; локальный тег удалить `git tag -d vX.Y.Z` и повторить.
- Расхождение с origin (тег существует): пуш падает — восстановление то же.
- Сборка без тегов в репо: `VERSION=dev` → `VER_NUM` пуст → 0.0.0 → первый тег `v0.0.1`.

## Проверка

1. `make help` — обновлённое описание.
2. Миграция: `git ls-remote origin` показывает `refs/tags/v0.0.1`, `0.0.1` отсутствует.
3. `make syso`: вывод `Tagging ... as v0.0.2`, тег на origin (`git ls-remote origin`), exe собран.
4. Свойства exe (Windows): FileVersion/ProductVersion = `0.0.2` (без `v` — в VS_VERSIONINFO числовые поля, префикс не попадает).
5. Повторный `make syso` → `v0.0.3` (инкремент от высшего `v`-тега).
