# Права: новые IP — всем, список PEER_IDS — для групповых команд и разрешённых чатов

## Контекст (текущее состояние после прошлого шага)

- `bhAnyWithMatch` (main.go:196-222): IP от «своих» (`allowed(FromID, PeerID)`)
  принимаются; от «чужих» — только уже отслеживаемые, плюс ответ
  «/новыеIP\n» + `ups` («Батюшка не благословляет…»).
- `bhAnyCommand` (main.go:301-336): ЛС от пользователя из PEER_IDS — два
  пульта (`kbGroup1`/`kbGroup2`); групповые чаты 200000000X и посторонние ЛС —
  одно «Ожидался список IP адресов…» без клавиатуры и без `ups`.
- `onMessageEvent` (main.go:225-265): snackbar c «Батюшка не благословляет…»
  при `my == false` (нажатие кнопок на чужих сообщениях).

## Решения (финальная спецификация пользователя)

1. **Новые IP принимаются от всех** — и в ЛС, и в групповых чатах
   (сообщество закрытое, посторонних нет). Гейтинг `allowed()` в
   `bhAnyWithMatch` и ветка «/новыеIP» + `ups` удаляются целиком.
2. **«Батюшка не благословляет…»** остаётся ровно в одном месте — snackbar
   `onMessageEvent` при нажатии кнопок на чужих сообщениях (`my == false`).
3. **Список PEER_IDS** по-прежнему определяет:
   - два пульта групповых …-команд — только в ЛС от пользователей из списка
     (bhAnyCommand, уже реализовано; в групповых чатах — реакция «как у
     чужих», по прежнему решению);
   - владельческие `/restart`, `/stop` (первый PEER_ID);
   - приветствие `bhNewMember` только в разрешённых чатах.
4. После снятия гейтинга `allowed()` нигде не используется → удалить;
   `notAllowed` остаётся (используется в `onMessageEvent`).
