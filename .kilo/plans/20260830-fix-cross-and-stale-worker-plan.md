# План: пропадает управление IP после пауз + ❌ не работает без IP

## Диагностика (по логу и коду)

1. **Главный баг — запущен устаревший бинарник.** Строки лога `main.go:290/313/120` совпадают не с HEAD (`79527f7`, там 335/359/121), а со старым коммитом `ba9203be`. В той версии `worker.go` ветка update была `else if cust.Cmd != ""`, а `else` (subscribe) безусловно делал `cus = append(cus, cust)`. Поэтому тиковый `ips.update(customer{})` (Cmd=="" и MsgID==0) попадал в subscribe → в `cus` появлялся нулевой customer. На следующем тике цикл отправки делал `sendKeyboard(0, 0, ...)` → VK `peer_id is invalid` → `ips.del(ip)` → воркер умирает → `🏓 ∅`, управление 127.0.0.1 пропадает.
   - В текущем HEAD (`worker.go:43`) условие уже исправлено на `else if cust.MsgID == 0`, и `customer{}` больше не попадает в `cus`. Но бинарник не пересобран.

2. **❌ при пустом списке IP не работает** — актуально и для HEAD: в `onMessageEvent` (main.go:389) стоит ранний `if ips.count() == 0 { return nil }` до обработки `❌`. Воркера уже нет, поэтому `ips.write` не вызывается, и сообщение со статусом не удаляется.

## Задачи

1. **main.go, `onMessageEvent`:** обработать `❌` до раннего выхода по `ips.count() == 0`. Если Data == "❌" и `ips.count() == 0` — удалить сообщение с кнопками напрямую, как ветка `❎`:
   ```go
   if Data == "❌" && ips.count() == 0 {
       if tm.ID > 0 {
           if err := deleteMessage(obj.PeerID, tm.ID); err != nil {
               let.Println(err)
           }
       }
       return nil
   }
   if ips.count() == 0 { return nil }
   ```
2. **worker.go (защита от регрессии):** в цикле отправки пропускать подписки без peer:
   ```go
   if cu.PeerID == 0 { continue }
   ```
   перед `if cu.ReplyID == 0 || status != statusOld` (и аналогично в ветке ❌-удаления `cu.PeerID == 0` уже не даёт deleteMessage, там ок).
3. **Пересборка:** `go vet ./...`, `go mod tidy`, затем `make win` (по AGENTS.md) — чтобы заработали уже имеющиеся исправления HEAD.

## Проверка

- Собрать `make win`, запустить, подписаться `/127.0.0.1`.
- Сделать несколько ⏸️ / 🔁 (в т.ч. групповых …⏸️ / …🔁), дождаться тика: отправок на peer 0 быть не должно, воркер жив, `Ping`/`IPS` управляемы.
- Удалить все IP (или дождаться их исчезновения), нажать ❌ на старом статус-сообщении — сообщение должно удалиться, без `∅`-заглушки в ответе... (ответ-снекбар остаётся, это ок).
- Нажать ❌ при живых IP — прежнее поведение (воркер удаляет все ответы и завершается) не сломано.

## Риски

- `❌` при count==0 использует `tm.ID` (глобальный id) — ветка `❎` уже делает так же, паттерн проверен.
- Правка в worker.go минимальна и не меняет логику подписки.
