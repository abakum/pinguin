# План: очередь накопившихся сообщений + маркеры ⏹️🏓/▶️🏓

## Цель
1. При старте бот дочитывает из истории **всех диалогов из `pinguin_ids`** — и групповых чатов (`2000000xxx`), и личных (ID пользователя) — текстовые сообщения, накопившиеся **от времени последнего stopH до текущего старта**, и обрабатывает их штатным роутером `onMessageNew` — эмуляция очереди Telegram.
2. Заменить служебный спам в чате первого ID: `💥 stopH <nil>` → `⏹️🏓`, `💥 startH <nil>` → `▶️🏓` (ошибки по-прежнему показываются с `💥`).

## Решения (согласованы)
- В `pinguin.json` хранится только **время последней остановки** `stopAt` (unix); время старта известно в момент запуска. Окно догонки = `[stopAt, startAt]`, ID сообщений не хранятся.
- Реплеятся **все события в окне**: текстовые (`Action.Type == ""`) через штатный роутер `onMessageNew` (IP, команды, ответы «-») и события действий (`chat_invite_user`/`chat_kick_user` → приветствие/прощание) — пользователь не видел их отработки в офлайне.
- От сообщества (`FromID < 0`) текстовые обрабатываются только помеченные `🏓` (CLI-отправки); статусные отчёты с IP без маркера не реплеятся — иначе зациклится подписка. На события действий фильтр `FromID` не распространяется.
- Первый запуск или крэш без записи `t` → догонки нет (только baseline).

## Изменения

### 1. `global.go`
- `var stopAt int64` — unix-время последнего stopH.

### 2. `json.go`
- `config`: добавить поле `T *int64 \`json:"t,omitempty"\``.
- `saver`: записывать `&stopAt`.
- `loader`: при ненулевом `T` присвоить `stopAt`.

### 3. `vk.go` (или `main.go`) — маркеры
- Хелпер `sendStatus(marker string, err error)`: `err != nil` → отправить `"💥 "+err`, иначе `marker` (тот же `MessagesSend` в `chats[0]`, что в `SendError`).
- Заменить вызовы:
  - `SendError(fmt.Errorf("stopH %v", stopH(ttCancel, bh)))` → `sendStatus("⏹️🏓", stopH(ttCancel, bh))` (closer.Bind и рестарт в тикере);
  - `SendError(fmt.Errorf("startH %v", err))` → `sendStatus("▶️🏓", err)` (старт и рестарт).

### 4. `main.go` — догонка
- В `closer.Bind` до `stopH(...)`: `stopAt = time.Now().Unix()` (saver сохранит при выходе) — это единственное, что пишется в `.json`.
- Функция `catchUp()`, вызывается после `CreateBot` и **до** `startH(...)` (чтобы live-события не задублировались); `startAt := time.Now()`:
  - для каждого `peer` из `chats` (групповые `2000000xxx` и личные диалоги — ID пользователя): `messages.getHistory` `count: 200`;
  - всегда обновлять `lastMsg[peer]` максимумом ID (poller не будет реплеить до-стартовый backlog);
  - если `stopAt > 0`: элементы с `Date` в `[stopAt, startAt]` прогнать через `onMessageNew(&tm)`, пропуская только собственные текстовые без маркера: `Action.Type == "" && FromID < 0 && !strings.HasPrefix(tm.Text, cliMark)` (действия входа/выхода реплеятся);
  - протокол: одна строка на peer — сколько обработано (только при N > 0) и ошибки запроса.
- Лимит: одно `getHistory` на чат, максимум 200 сообщений за окно; больший backlog обрезается — принять как ограничение.

### 5. Взаимодействие с поллером
- `catchUp` заполняет `lastMsg`, поэтому первый опрос поллера не станет реплеить старое.
- `pollSoon()` из реплея через `onMessageNew` — безвреден (дебаунс 5 с уже есть).

## Риски
- Реплей `/`-команд повторно отправит клавиатуры (следствие выбора «все текстовые»).
- Реплей действий входа повторно отправит приветствие — корректно для событий за окно простоя, но если событие уже было отработано до остановки и попало в окно (перевод часов), приветствие задублируется.
- Часы переведены назад → окно пустое/широкое; терпимо (дубли подписок идемпотентны: `ips.write` в существующий канал).

## Проверка
- `go vet ./...`, `go mod tidy`, `make win`.
- Ручной сценарий: остановить бота → отправить в чат сообщение с IP и `pinguit`-сообщение → запустить бота → IP подписаны, в логе `catchUp` N>0; в чате видны `⏹️🏓` и `▶️🏓` вместо `💥 stopH <nil>`; поллер не реплеит то же сообщение второй раз (по протоколу `poll ... cli message:`).
- Рестарт без офлайн-сообщений: `catchUp` обрабатывает 0, дублей ответов нет.

# Отчёт о реализации (2026-08-28)

## Что сделано (итоговое состояние репозитория)

### 1. CLI-отправка в самом pinguin
- `main.go:20-27` — при `len(os.Args) > 2` режим разовой отправки: `pinguin <peerID> <текст...>`, longpoll не стартует, `elevateIfNeeded()` пропускается; ошибки → stderr, exit 1.
- `vk.go` — `sendPlain()` (голый `MessagesSend` без клавиатуры, `random_id: 0`) и `cliSend()` (парсинг peer, токен из `pinguin_token`: env / `.env` / Credential Manager). Проверка по `pinguin_ids` не выполняется.
- Промежуточный вариант с отдельным `cmd/pingit` и build-тегом `send` был отклонён: один исходник, различие бинарников только в манифесте.

### 2. Поллер собственных CLI-сообщений (VK longpoll не шлёт `message_new` для исходящих сообщества)
- `cliMark = "🏓"` — префикс CLI-сообщений (zero-width space U+200B VK обрезал).
- `pollOwnMessages()` — `messages.getHistory` по каждому peer из `pinguin_ids` (и групповые, и личные); обрабатывает только свои сообщения (`FromID < 0`) с префиксом `🏓` → `bhAnyWithMatch` → подписка IP → воркер отвечает с `reply_to` («сам написал — сам ответил»).
- `poller()` — `getHistory` сразу после любого longpoll-события (`pollSoon()` в `onMessageNew`/`onMessageEvent`), затем минута простоя (`refresh`); дебаунс 5 с; протокол только по обнаружению (`poll ... cli message:`).
- `catchUp()` — при старте реплеит окно `[stopAt, startAt]`: все текстовые и действия входа/выхода через `onMessageNew`, кроме собственных текстов без `🏓`; всегда обновляет `lastMsg` (поллер не реплеит backlog).

### 3. Курсор простоя
- `global.go`: `stopAt int`; `json.go`: поле `t` в `pinguin.json` (пишет `saver`, читает `loader`); `closer.Bind` фиксирует `stopAt = time.Now().Unix()` перед `stopH`. Первый запуск/крэш → догонки нет.
- `loader()` перенесён до `startH()` (нужны `stopAt` и словарь; live-события не задублируются).

### 4. Маркеры вместо спама
- `vk.go`: `sendStatus(marker, err)` — ошибка → `💥 …`, иначе маркер. В чат первого ID идут `⏹️🏓` и `▶️🏓` вместо `💥 stopH/startH <nil>` (старт, остановка, рестарт по таймеру).

### 5. Сборка: два Windows-бинарника из одного исходника
- `app.manifest` (`requireAdministrator`) — оставлен для pinguin; новый `app_noadmin.manifest` (`asInvoker`, имя `pingit`).
- `Makefile`: таргет `versioninfo` параметризован `MANIFEST`; `win` собирает сначала `pingit.exe` со своим `resource_pingit_windows_amd64.syso` (иконка и versioninfo есть, элевации нет; syso удаляется после линковки, чтобы два `.rsrc` не встретились в одном билде), затем `pinguin.exe` с админ-манифестом. `make install` — один бинарь для Linux (оба режима).
- Варианты «pingit.exe вообще без syso» и build-тег `send` отвергнуты в ходе обсуждения.

## Отклонения от плана
- `stopAt` — `int` (не `int64`): поле `Date` у сообщения в vksdk имеет тип `int`.
- CLI-отправка оставлена внутри pinguin (отдельный бинарник pingit — это тот же код с другим манифестом, не отдельный источник).

## Проверка
- `go vet ./...`, `go mod tidy`, `make win` — чисто, собраны `pinguin.exe` и `pingit.exe`; в бинарях проверены встраивания манифестов (`requireAdministrator` / `asInvoker`).
- Подтверждено пользователем вживую: CLI-сообщение с `127.0.0.1` дошло, работающий бот подписал и ответил с `reply_to`; поллер по логу отработал baseline и обнаружение.
- Не проверено вручную (нужен боевой запуск): реплей действий входа/выхода за окно простоя, `catchUp` при backlog > 200 сообщений.
