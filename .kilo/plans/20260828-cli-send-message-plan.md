# План: разовая отправка сообщения из CLI

## Цель
`pinguin <peer_id> <текст сообщения...>` — отправить сообщение в VK и завершиться, не запуская longpoll-цикл. Первый аргумент — peer_id (пользователь, положительный, или чат `2000000000+chat_id`, например `2000000020`). Остальные аргументы склеиваются пробелом в текст.

## Решения (согласованы)
- Отправлять в **любой** ID без проверки по `pinguin_ids` (AAA).
- Отправка простым `MessagesSend` (random_id, message, peer_id), **без** inline-клавиатуры `kbIP` — это ручное сообщение, кнопки подписки не нужны.
- Сценарий «сам написал — сам ответил» обеспечивается другим, уже запущенным инстансом бота: CLI-инстанс только отправляет сообщение, а работающий longpoll-инстанс получает его через `message_new` и обрабатывает штатно (регэксп IP → подписка через `bhAnyWithMatch`, ответ через `sendKeyboard` с `reply_to`). Изменения в `onMessageNew` не требуются.
  - Примечание для проверки: у сообщения от сообщества `from_id` отрицательный (ID группы). Убедиться, что роутинг `onMessageNew` (`main.go:163-190`) не отбрасывает такие сообщения до проверки `reIP`.
- Ошибка отправки → вывод в stderr, exit code 1. Успех → exit 0.

## Изменения

### 1. `vk.go`
Добавить функцию (рядом с `SendError`, стиль `vk.go:140-148`):

```go
func sendPlain(peerID int, text string) error {
	_, err := bot.MessagesSend(api.Params{
		"peer_id":   peerID,
		"message":   text,
		"random_id": 0, // либо rand.Int63, как в существующем коде
	})
	return err
}
```

Уточнить при реализации, как задаётся `random_id` в остальных местах (`sendKeyboard`, `vk.go:82-99`), и использовать тот же приём.

### 2. `main.go` (`main()`, `main.go:19`)
В начале `main()`, после инициализации логов и **до** запуска долгих вещей (до `CreateBot`/`startH`/`loader`):

```go
if len(os.Args) > 2 {
	if err := cliSend(os.Args[1], strings.Join(os.Args[2:], " ")); err != nil {
		log.Fatal(err)
	}
	return
}
```

`cliSend(peerArg, text string) error` (в `main.go` или `vk.go`):
- распарсить peer_id через `strconv.Atoi` (ошибка → понятное сообщение в stderr, exit 1);
- `bot, err = CreateBot(envValue("pinguin_token"))` (токен из env/.env/Credential Manager как обычно);
- `return sendPlain(peerID, text)`.

Важно: не трогать глобальный `chats = NewAAA()`/`pinguin_ids` — для разовой отправки он не нужен (не проверяем).

## Проверка
- `go vet ./...`, `go mod tidy`, затем `make win` (по AGENTS.md).
- Ручной тест с реальным токеном:
  - `./pinguin 2000000020 test message` — сообщение появляется в чате;
  - `./pinguin 123456789 test` — личка пользователя;
  - `./pinguin abc test` — ошибка парсинга, exit 1;
  - `./pinguin` (0 или 1 аргумент) — обычный запуск longpoll-режима, поведение не изменилось.
- Сценарий «сам написал — сам ответил»: при запущенном longpoll-инстансе выполнить `./pinguin <peer> <текст с IP>` — работающий бот подписывает IP и отвечает на это сообщение (проверить, что событие от `from_id` группы обрабатывается).
