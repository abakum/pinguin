# Кнопка «…» в kbOwner: отчёт по всем хостам (реализовано)

Дата: 2026-10-07. Статус: реализовано, собрано (`go vet`, `go mod tidy`, `make win`).

## Контекст

- Ответ на `/` в ЛС разрешённого пользователя — закрепляемая панель с клавиатурой `kbGroup` (2 ряда) или `kbOwner` (3-й ряд: `⏹️🏓` `▶️🏓`) — main.go, vk.go.
- Статусы (`✅`/`❗` + суффикс `⏸️`) и подписчики (авторы запросов) живут локально в горутинах `worker()`; JSON их не содержит: pinguin.json пишется только при остановке и хранит лишь customer-записи без статусов.

## Принятые решения

1. Кнопка только в `kbOwner`; `kbGroup` не менялась.
2. Первая кнопка 3-го ряда: метка `…`, payload `…`, цвет `secondary` (без заливки).
3. Источник данных — центральный снапшот в памяти (НЕ JSON): воркеры обновляют глобальную карту `hosts`, тап читает её напрямую.
4. Вывод — один агрегированный reply на сообщение панели, по строке на хост.
5. В строке хоста и в статус-реплая — обычный текст без кликабельных mention (меньше шума от уведомлений).
6. Маркер автора в статус-реплае: `Имя @id<N>` обычным текстом; автор кнопок парсится из него (`reAuthor`), без дополнительных карт.

## Внесённые изменения

### vk.go

- `kbOwner`: 3-й ряд — `…` (`secondary`, перехватывается по точному совпадению до ветки групповых `…`-команд), затем `⏹️🏓`, `▶️🏓`.
- `sendStatusReply`: текст reply теперь `<статус> <ip> <Имя Фамилия> @id<userID>` одной строкой (без `\n` и без `—`).
- `userMention`: возвращает `Имя Фамилия`, пустая строка при неразрешимом имени (кэшируются только успешные разрешения); без `[idN|Name]`. Идентификатор автора всегда есть в маркере `@id<N>`, поэтому `#N`-fallback удалён.

### global.go

- Новое поле `hosts = sHosts{m: map[string]hostState{}}` и типы:
  - `hostState{Status string; Cus customers}` — последний статус воркера + копия подписчиков;
  - `sHosts` (RWMutex-карта) с методами `set`/`del`/`list` (list возвращает копию).
- `replyOwners` удалён: автор определяется из маркера `@id<N>` в тексте reply (покрывает и pingit-запросы, чей reply-родитель — сам бот).
- `reAuthor` теперь `@id(\d+)\s*$` — только маркер `@id<N>` в конце текста, без fallback.

### worker.go

- `defer hosts.del(ip)` рядом с `defer ips.del(ip, false)`.
- `hosts.set(ip, status, cus)` после чистки подписчиков в кейсе `cmdVerify` и в конце обработки события (покрывает load/subscribe/update/смену статуса).

### main.go

- Константа `cmdReport = "…"` в блоке рядом с `cmdStop`/`cmdRestart`.
- `onMessageEvent`: блок `Data == cmdReport` (после stop/restart, до групповых `…`-команд) — проверка владельца как у stop/restart, в горутине шлёт `hostsText()` как reply на сообщение панели без клавиатуры.
- Определение автора кнопок: 1) `reAuthor` — маркер `@id<N>` в конце текста; 2) `ReplyMessage.FromID` (реплаи без маркера).
- `hostsText()`: по строке на хост `<статус> <ip> <авторы>` (без `—`), уникальные авторы: имя из `userMention`, при пустом имени — `@id<N>`; сортировка по ip, `∅` при пустой карте; импорт `sort`.

### json.go

- Не менялся: `ReplyID`/`UserID` и так сохраняются в pinguin.json, маркер `@id<N>` восстанавливается в тексте reply.

## Форматы вывода

- Тап на `…`: 
  ```
  ✅⏸️ 10.85.5.44 Константин Абакумов
  ❗ 10.85.5.45 Иван Петров
  ```
- Статус-реплай: `✅⏸️ 10.85.5.44 Константин Абакумов @id123456`.

## Крайние случаи

- Хостов нет → `∅`.
- Воркер до первого пинга → строка без статуса, самокорректируется.
- Выход воркера → `defer hosts.del(ip)`, снапшот не течёт.
- Одновременные тапы независимы: читается копия карты.
- pingit/CLI-запросы: автор определён по маркеру `@id<N>` в тексте reply, а не по reply-родителю (родитель — сам бот).
- `cleanupOrphans`/`catchUp`/`saver` не затронуты; схема pinguin.json не менялась.

- `go vet ./...` — чисто; `gofmt -l .` — пусто; `go mod tidy`; `make win` собрал `pinguin.exe`/`pingit.exe`.
