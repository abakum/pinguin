# CLI-статусы: управление кнопками автором триггера

Дата: 2026-10-07. Реализовано полностью (все пункты ниже — внесённые изменения).

## Контекст

CLI one-shot вызывается с разными триггер-перами (`pinguin.exe 458674420 2000000001 …`, `pinguin.exe 229928246 2000000001 …`). Триггер `🏓<peer> …` в ЛС ловится в `MessageReply` (main.go), запрос уходит в целевой чат от имени бота, а `customer.UserID` брался из `tm.FromID` — id сообщества (отрицательный). Статус-реплай отвечал на сообщение бота (`reply_to: GlobalID`), поэтому в `onMessageEvent` проверка `my = obj.UserID == tm.ReplyMessage.FromID` была всегда false → «Батюшка не благословляет Вас».

## Внесённые изменения

### 1. Автор триггера вместо id сообщества

- **main.go, `MessageReply`**: `UserID: tm.FromID` → `UserID: tm.PeerID` — в ЛС peer == user id автора триггера (229928246 / 458674420).

### 2. Автор хранится в тексте статус-ответа (для всех ответов)

- **vk.go, `sendStatusReply`**: при `cu.UserID > 0` к тексту добавляется строка-маркер с автором.
- **vk.go, `userMention`**: маркер — кликабельное упоминание `[id<N>|Имя Фамилия]` через `users.get` с кэшем `userNames sync.Map`; при ошибке API — фолбэк `#N`.
- **global.go**: `reAuthor = regexp.MustCompile(`(?m)^(?:\[id(\d+)\|[^\]]*\]|#(\d+)\s*)$`)` — распознаёт оба формата.
- **main.go, `onMessageEvent`**: в групповом чате автор кнопки = id из маркера в тексте ответа; старые ответы без маркера — прежний фолбэк `ReplyMessage.FromID`. Права переживают рестарт без изменения формата `pinguin.json` (маркер восстанавливается из сохранённого `UserID`).

### 3. Удалены лишние поля JSON (`gid`, `status`)

- **global.go, `customer`**: убраны `GlobalID` и `Status`; остались `PeerID`, `UserID`, `MsgID`, `ReplyID`, `Cmd`, `Deadline`.
- **main.go, `MessageReply`**: после отправки CLI-эха его conversation message id узнаётся хелпером `convMsgByID` (vk.go, скан свежей истории по global id от `messages.send`) и пишется в общий `MsgID` — CLI и чат-пути унифицированы.
- **vk.go**: `sendStatusReply` — один путь через `sendKeyboard`; `requestExists` использует только `msgExists`; `msgExistsGlobal` удалён.
- **worker.go**: ветка загрузки без `cust.Status` (статус восстанавливается первым пингом и обновляет ответ); условия `MsgID == 0 && GlobalID == 0` → `MsgID == 0`; при сохранении `Status` больше не пишется.

### 4. Отсутствие pinguin.json — не ошибка

- **json.go, `loader`**: если файл не существует — лог `not found, starting empty`, создание файла с пустой конфигурацией, работа продолжается. Другие ошибки чтения/парсинга по-прежнему фатальны.

## Поведение

- 229928246 и 458674420 управляют только своими хостами (маркер своего id в ответе); остальные получают отказ.
- Старый `pinguin.json` (с `gid`/`status`/отрицательным `user`) удалён, начат с нуля — предыдущие версии его полей больше не читают.

- `gofmt`, `go vet ./...`, `go mod tidy`, `make win` — пройдены после каждого этапа.
